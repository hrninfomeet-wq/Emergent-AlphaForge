# Conditional adapters checkpoint

Implemented source files (syntax checked; behavioural campaign deferred as requested):

- `backend/app/conditional/market.py`: JSON/CSV public Upstox masters, full-key plus expiry/strike/type/lot join, freshness evidence, no guessed tick default. CSV supplies the price-unit tick; raw JSON must agree either directly or with currency minor-unit scaling. Live adapter independently compares broker `ls`/`ti`.
- `backend/app/conditional/broker.py`: paper observations derived from persisted actions, strict live symbol/metadata preparation, stable remark/order observations, cancel readback, monotonic stop amendment, foreign-position detection, and shared exit claim plus fresh residual/reserved-sell checks.
- Authorized additive `UpstoxMarketStreamManager.ensure_instruments`: subscribes added keys on the active socket and retains them for reconnect, without restarting the shared feed.

Interface integration: root owns `submit_conditional_intent` in the existing executor. Live exit/stop actions must carry `owned_actions` (persisted actions for the parent order) so the gateway can prove residual ownership. Current action is excluded from that set during pre-send reconciliation. Gateway `quote(contract)` supplies a checked authenticated fallback quote for stale-feed exits.

Resume checkpoint 2026-10-26: added `ready()` (configuration/latch/client availability only), `exit_reference(order)` from persisted resolved contract, amendment confirmation flag from broker price readback, strict current order limit/trigger matching, and position snapshot caching alongside order snapshots. Entry now takes the same symbol claim as global exits and performs fresh ownership reconciliation before transmission. Exit capacity reserves every working sell. Cancel and modification also take the symbol claim. Reconciliation can resolve a trigger-time contract before the first action, rejects foreign working orders and foreign product exposure, and retains valid persisted terminal fill observations when the next day's order book omits historical orders. Nonterminal absent observations remain unresolved. Market subscriptions accept dictionaries or instrument-key strings.

Confirmed: AST parsing passed for `market.py`, `broker.py`, `upstox_stream.py`, and `tests/test_conditional_adapters.py` using Python `ast.parse`. This is syntax evidence only. Tests were authored/updated, not executed in this resumed adapter task. No production requests or authentication/order operations were made.

Pending-amendment integration: root persists `pending_amendment={trigger_price,limit_price}` before transmission. The adapter accepts only the original or pending price pair and returns `amended`, `limit_price`, and `trigger_price` on stop observations. Modification refuses to transmit without this pending record; already-applied readback avoids another modification. An unchanged readback retains the pending record for later reconciliation. Arbitrary broker price changes remain UNKNOWN. This source path is syntax checked, not behaviourally tested. Exit/stop quantities accept integral odd residuals from partial fills; only entries require whole lots, and all children remain freeze-bounded.

Lesson: a terminal order missing after a daily book rollover differs from a nonterminal missing order. The former can use validated persisted broker observations; the latter cannot be presumed canceled. Confirmed approach: require independent current position evidence before any new sell. Dead end avoided: interpreting an ACK as cancellation or modification completion.

Not verified: live requests, current CSV endpoint contents, actual tick-unit join, broker acceptance/margin, websocket hot-add against Upstox, test campaign. No order or authentication operation was performed. Primary documentation: https://upstox.com/developer/api-documentation/instruments/ documents both master formats and CSV tick example; its JSON field description does not explicitly state tick units, so no direct divide-by-100 assumption is used as the sole tick source.
